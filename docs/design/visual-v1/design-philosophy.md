# Court Margin / 球场页边

这套视觉语言把网球知识看作一本会被带到球场上的工作手册，而不是一条无休止的聊天记录。球场的边线成为页面的分栏，落点成为索引，练习之间的间隔成为留白。深石墨、纸白和克制的球场绿构成底色，金色只落在品牌字标和向前的球路上；只有正在阅读的句子、正在执行的一步和需要辨别的证据获得强调。界面不制造热闹，它帮助一个人把注意力留在一个问题上。

阅读是主景，Agent 是整理和连接内容的助手。桌面端用稳定的双 Wiki 导航、舒展的正文和可收起的证据栏形成秩序；手机端不压缩三栏，而是在同一条信息路径上逐层展开。技术 Wiki、个人训练 Wiki、训练卡与原始记录共享主题和来源线索，让阅读与练习之间的切换像翻页，而不是进入另一个产品。精心打磨体现在行长、基线、留白和细线的对齐中，而不是装饰数量中。

文字具有两种音量：中文标题清楚、直接，英文衬线编号像纸质手册的章节标记；元信息则退后为低声的等宽索引。概念图只画球场、轨迹与观察位置，不用伪精确的动作评分制造权威。图形中的虚线表示探索，实线表示组织，细小的圆点提示阅读或训练的位置。这些网球线索不必被解释，也能让使用者感到它属于球场。

证据差异必须可以被看见，也必须可以被读出。与资料关联的内容使用绿色标记和可定位的来源；模型补充使用独立的暖色容器，并明确写出“未经知识库核验”。个人感受保留为“本人记录”，不被 AI 改写成客观结论。颜色不是唯一信号，标签与结构共同承担区分责任；界面不出现没有依据的可信度百分比、教练认证或效果提升数字。

三张意向稿是同一产品的三种重心，而不是三套待开发的应用：A 把知识阅读放在中心，B 把一条知识转换成球场上的单次练习，C 让练后记录回到知识旁边。设计的最终张力是“资料足够丰富，眼前足够简单”。第一版应选择少数页面，把阅读、来源、训练卡与一条记录之间的关系打磨完整，而不是复制一个成熟阅读平台的功能总量。

## 已确认的手机补充方向

用户选择 A 的知识主结构，搭配训练卡和简单练后记录。新增 D 将手机流程拆成练前、练中、练后、提交后回看四屏，不扩成独立的比赛统计产品。它借鉴的是工作流，而不是第三方截图的构图：练习时少输入，事后保留原话，再回到相关资料。

用户进一步明确了核心：训练笔记不只是聊天上下文，还应被内置 Agent 整理成持续维护的个人训练 Wiki。个人派生页可自动更新；技术 Wiki 的改动先审阅；两者保留来源和版本，原始教程与原始训练笔记不能被 Agent 覆盖。A 已加入双 Wiki 与跨来源 Agent，D 的最后一屏展示个人主题页更新，而不是一次性聊天回复。术语见 [领域语言](./CONTEXT.md)。

离线范围已经确认：保存过的知识与训练卡可离线查看；记录保存在本机草稿，联网后由用户确认提交；新的 Agent 整理与 AI 生成需要联网。设计明确区分“本机草稿”“待提交”“已确认提交”和“Wiki 整理状态”，不把本机保存伪装成跨设备同步，也不把记录保存成功等同于 Wiki 更新成功。完成记录不强制填写感受，主观标签也不转换成技术能力评分。
